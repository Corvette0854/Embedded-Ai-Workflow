# 开发时，怎样把值得留下的东西记下来？

你照常使用已有工程和开发工具。需要整理时，把已有材料交给 AI，留下以后会再看的内容就好。

## 哪些东西值得留？

| 开发时发生了什么 | 知识库可以留下什么 |
| --- | --- |
| 弄懂了一个原理或一段代码 | 一篇解释清楚主线和具体例子的学习笔记 |
| 定位并处理了一个问题 | 现象、条件、真正做过的排查、修复与验证 |
| 一个阶段做完了 | 项目实际结果、版本、证据入口和总结 |
| 任务还没做完 | 现有记录中的停止位置与已决定的待办 |

代码、完整日志、构建和烧录方式继续留在工程真源。笔记保存必要内容和链接，避免两边各维护一套。

## 想让 AI 帮忙收尾，可以这样说

```text
依据本对话当前可见的材料，读取我指定的个人知识库规则，整理这阶段值得留下的内容。
先找已有记录，适合补原篇就补；保留具体操作、参数和证据。
把没运行、没核对和没理解的部分如实留下，整理到我指定的笔记位置。
```

建议在一个有结果的阶段整理，换对话前核对已保存的记录；具体时机与接续方式见[知识怎样留下来](知识怎样留下来.md)。工程状态与原始证据留在授权的工程位置，个人知识与经验按需关联，不用每类都生成。

日志出现数据、程序能编译、设备实际动作正确，分别支持不同结论。记录时写清观察了什么和条件；自己是否会用，由自己的实际表现决定。

## 如果确实想改善开发流程

先明确一个具体问题，再对照已有工程入口与适用工具给建议。是否改代码、加测试或接入自动化，由本次实际任务与授权决定；本包不主动给工程套一套新流程。

工具参考集中在[来源与取舍](已有方案与取舍.md)。建议采用前核对对应版本、平台与真实结果，别把看上去合理的示例当成已经适配的方案。
