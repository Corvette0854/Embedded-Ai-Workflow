# 知识怎样留下来：从随手丢，到下次用

学习、项目与踩坑笔记可以从同一个入口找到。材料整理交给 AI，阅读和判断留给自己。

真正值得复用的是这条日常路径：

```text
随手收下 → 核对内容 → 补原篇或新建 → 放到固定位置并关联
         → 下次查用或复习 → 把新理解补回原篇
```

## 当时没空整理，先收下

聊天片段、代码说明、截图和链接，可以先交给 AI 或放进自己的收集箱。没必要当场判断放哪、用哪个模板。

只想存一下，就说“只收集”。短到不足以成篇、还缺关键依据的内容先留在碎片区；等以后真正需要时再处理，不把每句话都扩成一篇。

## 真要整理，AI 负责这几件事

1. **先核对**。用户原文和 AI 解释都是输入；能核对的回到资料、代码或日志，错误先纠正，不能确认的如实留下。
2. **先找已有内容**。在允许读取的位置找同主题笔记。能承接就局部合并；只有以后会因一个独立问题搜索它，才新建。
3. **选用途，保留具体内容**。知识解释、项目链路和排障经验用不同骨架。参数、必要代码、真实步骤和证据不压成泛泛摘要。
4. **归档并连好**。按约定放到固定位置，补必要阅读入口；只链接真实存在、确有用途的条目。
5. **通读后交付**。删重复、空栏目与模板提示，检查标题和正文是否一致，简短说明写到哪里、改正了什么和什么仍未知。

归档时不会要求你重填一套表。AI 缺少影响结果的关键材料才问，已有约定继续沿用。

## 为什么分类和链接要一起用？

**位置按用途，关联按主题**。一篇显示问题的经验放在经验区，关于字符绘制的知识放在学习区；它们属于同一主题，可以一起出现在“显示”入口里，也互相链接。

- 总览：知道整个库有什么、从哪里进入。
- 主题入口：按当前领域集中看有关内容。
- 搜索：按自己会记住的问题词定位。
- 关联：从项目找到知识和经验，再回到项目。

初期用手工链接就够了。内容增加后，字段中的“领域”可以协助筛选跨目录条目；不要为了图谱数量加链接或复制正文。

## 打开以后，怎样快速恢复理解？

顶部放一句话主线和几个关键判断，下面保留真正能查用的例子、代码与步骤，详细来源和验证放后面。这样复习时可以短读，遇到问题时仍有细节。

学习笔记与适合回顾的经验笔记，顶部可以配一个口述问题，答案默认折叠，想核对才点开。快速区不重复整篇内容，也不要求先答题才准读。想深入时再看后面的例子与证据；AI 整理或辅助排障时也按需要读取后面的细节。

想继续复习时说“按这篇带我回顾”；有新理解补回原篇。已解决的案例不用因此安排新训练，用户不需要口述问题时可以取消。

AI 核对了资料，不等于你已经掌握。学习笔记区分资料依据与掌握程度，项目和经验记录写实际观察与结果。

## 在项目对话里，什么时候整理？

通常在正在做事的对话里整理更方便：那里的可见材料包含刚做的观察、判断和修改，不必重新口述全过程。一个问题查清、一个模块阶段结束、发现值得复用的判断，或者准备换对话时，就可以整理。无需等整项目结束，也不把每轮聊天存一篇。

先留下阶段结果与证据入口，在授权的工程记录位置更新；值得复用的知识与经验，再整理到个人库。同主题已有好记录就补原篇或链接过去，不长期复制两套正文。没有跨目录写入能力时，先给内容和目标位置，由本人保存或交给有权限的助手。

可以在当前项目对话说：

```text
读我指定的个人知识库入口和整理规则，依据本对话当前可见的材料及授权文件，整理这阶段值得留下的内容。
先补已有记录：知识、实际排障和项目进度各按用途处理，不要求每次同时生成三篇。
保留必要细节、本人/AI/他人的实际参与和证据；没有依据的不要补成已完成。
保存到已约定的位置，告诉我更新了哪篇、什么仍未知；换对话需要的进度留在项目入口。
```

保存后核对关键内容再开新对话，让它先读项目入口、有关原始证据与实际采用的知识库规则。一个模块一个对话是可选习惯；跨模块问题可以留在同一条线里，不按固定轮数强制切换。

长对话里如果反复忽略约束、沿用旧假设或漏掉已确认结果，先回到文件和证据核对，必要时换对话。不能仅凭“聊得长”认定模型变笨，也不能假定当前助手还能看到所有早期消息。材料缺失时留下缺口，不凭印象补齐历史。

## 面试前，怎样从自己的知识库里挑内容？

提供岗位要求、准备时间，以及允许读取的知识库范围，让 AI 先按岗位相关性和本人真实参与选择少量记录。先看已有笔记顶部恢复主线，想口述再展开答案；被追问细节时回到后面的代码、排查与证据。

例如岗位关注 MCU 通信与联调，AI 可以选择有关通信链路、接收处理和真实故障的笔记，说明每篇为什么相关，再带你回顾“现象是什么、怎样缩小范围、改了什么、怎样验证”。没有岗位材料时先了解方向，不凭空假定岗位需求。

默认在对话里给阅读顺序或链接，不复制整套面试笔记。只有本人需要保存时，才在自己的私有位置留下短入口。个人职责、独立完成范围、公司信息与实测结果如实表达，不把 AI 整理包装为本人能力，也不保证任何面试官偏好或求职结果。

## 采用以后，你平时只需要说什么？

| 你说 | 系统怎样处理 |
| --- | --- |
| 只收集这段 | 先保留，不扩写 |
| 整理收集箱 | 在约定范围批量核对、合并、分类、关联；不足成篇的继续留存 |
| 整理这段 / 记录这个坑 | 按已有约定处理，优先补同主题 |
| 补到某篇 | 局部合并，通读去重 |
| 按这篇帮我复习 | 用有关内容提问和反馈，必要时更新本人确认的新理解 |
| 只解释，不记录 | 留在对话里 |

首次采用时，把入口、允许读取/写入范围和少量整理约定确定下来，以后无需逐次确认同一位置。AI 在你发材料或提出整理任务时执行；本包没有后台整理服务。

## 哪些可以按自己的习惯调整？

分类、字段、口述问题和主题入口，都以方便自己查用为准。先用普通链接与搜索，内容增多后再考虑按领域汇总，不必一开始装插件或固定复盘频率。

[Dataview](https://blacksmithgu.github.io/obsidian-dataview/)可按字段汇总笔记，是可选插件；折叠块与属性是 [Obsidian 原生功能](https://obsidian.md/help/callouts)，不依赖它。

看内容能否再次找到、读懂和用上，再决定留下哪些整理约定。
