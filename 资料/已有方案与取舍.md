# 这个包参考了什么，侧重在哪里？

主要方向是个人知识库：让知识、项目、经验和踩坑记录容易阅读、找到和继续补充。示例偏嵌入式，整理方式按本人习惯与软件适配。

## 知识库与文档参考

| 原始来源 | 本包采用的思路 |
| --- | --- |
| [Obsidian 的建库说明](https://obsidian.md/help/vault)与[存储说明](https://obsidian.md/help/data-storage) | 文件式笔记可以从个人文件夹和少量实际内容开始；这只是本包示范的载体，其他软件同样按自己的方式使用 |
| [Obsidian 的内部链接](https://obsidian.md/help/links) | 有关系的内容相互链接，详细事实尽量只维护一份 |
| [Kepano 的知识库说明](https://stephango.com/vault)与[示范库](https://github.com/kepano/kepano-obsidian) | 借鉴长期组织：少量模板、主题关联与持续回看；沿用用户自己的分类与字段，不照搬作者的生活分类或目录习惯 |
| [LeanProductivity 的首次安装说明](https://wiki.sascha-kasper.com/obsidian/lean-vaults/setup/install-the-lean-starter-vault/) | 借鉴首次上手：显眼的先读入口、可浏览的成品、逐步开始；不引入其插件组合，也不要求先搭完整系统 |
| [Diátaxis](https://diataxis.fr/) | 区分理解知识、照着操作、查参考等不同阅读需要，避免一篇笔记塞进所有用途；不要求用户复制四套目录 |

入口先展示用途与成品，内容从少量笔记逐步增加。折叠块按口述答案、具体例子与补充说明区分用途，语法见 [Obsidian 原生提示块说明](https://obsidian.md/help/callouts)。颜色与图标随主题变化，其他阅读器可能直接展开。

可选汇总参考 [Dataview 原作者文档](https://blacksmithgu.github.io/obsidian-dataview/)，折叠答案参考 [Obsidian 提示块](https://obsidian.md/help/callouts)。基础示范使用静态链接，不安装插件也能阅读。

## 开发资料只作按需参考

此前查阅过以下原作者或官方资料，用来检查记录中的证据与验证表述。它们不组成使用本包的必修流程：

- [Superpowers 的系统排障方法](https://github.com/obra/superpowers/blob/main/skills/systematic-debugging/SKILL.md)、[GitHub Spec Kit](https://github.com/github/spec-kit)：任务与证据组织。
- [PlatformIO 单元测试](https://docs.platformio.org/en/latest/advanced/unit-testing/index.html)、[Zephyr pytest 集成](https://docs.zephyrproject.org/latest/develop/test/pytest.html)、[ESP-IDF 单元测试](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/unit-tests.html)：各生态已有测试能力，是否采用看实际工程与版本。
- [Interrupt 的嵌入式单元测试经验](https://interrupt.memfault.com/blog/unit-testing-basics)、[Memfault 的开发里程碑](https://memfault.com/blog/accelerating-iot-device-development-through-npi-and-firmware-milestones/)：软件隔离测试、硬件验证和实际交付的区别。

本包侧重知识与经验记录。[开发中的记录建议](开发协作参考.md)只供有需要时参考，现有工程照常使用。

## 怎样选择采用的部分？

先看自己的材料和软件需要什么，再取有用的组织方式。不必复制整套模板或插件；引入第三方实现时核对版本、适用范围与许可证。

以上链接是可继续查阅的来源，不要求全部读完。是否有帮助，以自己的整理与查用结果判断。
