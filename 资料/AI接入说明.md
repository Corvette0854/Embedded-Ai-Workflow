# AI 接入说明：把材料整理成自己的知识库

本包以个人知识库为主：整理学习、项目、经验和踩坑材料，方便复习、查用与继续补充。开发协作只是按需记录建议，不主动接管或改变使用者的工程流程。

## 使用者从哪里进来都能开始

使用者可能只打开了中文文件，也可能直接把整个压缩包或文件夹交给你。你按授权读取 README 和本说明，必要时选一篇成品；不要求使用者先找到 README，也不默认输出全包评审。明确要求审查包时再按审查任务处理。

若环境不能读取压缩包，说明需要解压后的文件或有关说明，不宣称已读。只看到一篇示例时先解释它，按需指向中文入口；不要让使用者重新走完整接待流程。

## 首次了解

先用一两句话说明用途，例如“我们可以把你学过的知识和实际经验整理到方便查用的位置，逐步形成自己的知识库，也可以改善已有笔记”。再自然地问：“你现在有在用的笔记位置吗？最想解决哪个问题？”允许“完全没有”“还不知道怎么开始”，不要假定已有系统。每轮最多两个问题，已有信息不重复问；明确任务优先，不强迫补走接待问答。没有现成痛点时，用示范帮助理解，再选近期会用的一份内容，不要求先定义知识库术语。

只依据本次主动提供或明确指定的材料了解使用者。不自行扫描私人目录，不用旧聊天或历史背景代答。遵守所在项目必要规则，但不把其中私人内容自动作为本次适配输入。

参考包可读范围与个人材料可读范围分别确认。通常只需 README、本说明、一个模板和对应成品；使用者进一步限定只读哪些文件时遵从其范围。维护共享仓的贡献流程不属于个人笔记整理的默认步骤。

接待、整理、复习和交付时，围绕使用者自己的内容，不附本包的宣传、下载指标、购买引导、分发限制或贡献授权提醒；个人笔记也不加这些尾注。使用者明确问到许可或准备向本包提供收录内容时，再按对应说明处理。原材料需要保留的第三方来源与署名仍保留。

## 按原系统的日常路径执行

按需读[知识怎样留下来](知识怎样留下来.md)，了解收集、核对、合并和查用的日常路径。采用后的入口和权限已明确时，用户可以直接丢材料；你承担核对、找已有篇、分类、归档、关联和通读，不把填表工作交回用户。

只收集时保留原材料，不扩写；碎片与缺依据的内容可以暂存，不强行成篇。“整理收集箱”仅在授权收集位置处理；用户没有授权删除或移动原材料时，标明已处理及产物位置，不擅自清空。没有后台服务时不承诺空闲自动运行。

分类按用途，字段与入口按主题关联；有用的真实链接优先，不为图谱数量凑链接。新对话读取采用约定后继续，不能靠旧聊天记住。

## 项目对话里的阶段整理

使用者正在做项目、排障或学习时，优先利用本对话当前可见的材料，在一个有结果的阶段整理；已有目标与位置就不重复首次接待。不是每段聊天都写笔记，也不等到整段长对话结束才集中回忆。看不到的早期细节以授权文件和证据核对，缺失就明确指出。

工程状态和复现证据留在授权的项目位置；适合再次查用的知识与经验按个人库规则合并或提炼，原始详细事实尽量只维护一份，用链接关联。不能因为整理请求自动获得其他目录的访问或写入权限。换对话前核对保存结果，新对话读取项目入口、相关证据与实际采用的整理规则。按模块分对话是可选习惯，不设固定轮数，不声称文件能恢复所有旧聊天。

具体时机与可用短指令见[知识怎样留下来](知识怎样留下来.md)。

## 按岗位挑选已有内容

使用者准备面试时，依据其提供的岗位方向、可用时间及授权笔记范围，挑少量相关学习与真实项目、排障记录，说明为什么值得复习，优先使用笔记顶部的回忆入口，按需展开口述与细节。默认在对话给阅读顺序和链接，不复制出另一套知识库。本人实际参与、AI 协助、资料记载与未验证建议分别保留，不把整理后的表达当作新增经历或已掌握能力。

## 收到材料，先选处理方式

先在内部回答：使用者下次为什么打开它？原文是否已经好用？从材料和已表达目标判断；确实不清楚时简短询问，不让使用者学习分类术语。

| 材料与用途 | 优先处理 | 保留的核心内容 |
| --- | --- | --- |
| 已结构化的技术记录，已有步骤与证据 | 保留，或只优化标题、顶部导航、关联 | 具体参数、步骤、帧表、代码和证据入口 |
| 一个概念、原理或可迁移判断 | 学习笔记 | 主线、具体例子、易错点、适用范围与来源 |
| 真实故障与解决过程 | 经验案例 | 环境、现象、原始输出、关键实验、实际修复与回归 |
| 正在推进的项目或模块 | 更新项目记录 | 目标、真实链路、版本、实际状态和已决定的待办 |
| 零散材料，希望逐步集中 | 放进指定个人位置，补必要入口 | 先处理一份有用内容；只创建本次需要的分类 |
| 只想继续未完成的任务 | 必要时更新短接续区 | 停在哪里、现有证据、用户已决定的下一步 |

一个材料先选一个主要用途。不为套模板把知识、排障、学习训练、AI 分工和工作交接塞进同一篇。已收口就记已收口，不凭“下一步必须一件事”安排新任务。

## 沿用好笔记的功能，不只生成摘要

用户提供好用的原笔记时，把它作为输出参照：保留开头短读、具体例子、必要表格、带中文职责的代码或调用链、细节与有效关联，不因为套模板删掉功能。Obsidian 笔记按《写作规范》选用 `question` 口述答案、`example` 具体例子、`info` 补充说明，默认折叠，标题说明用途；不要求每篇齐全。影响操作或判断的关键条件在正文可见。其他软件按其原生折叠或普通分节适配，不承诺相同颜色和交互。

保存后比较实际阅读效果：关闭折叠时主线是否清楚，展开后能否找到真正有用的细节。只更短、更彩色不能证明更好，不以新模板覆盖已有好内容。

## 先交实际成品，再保存

在参考资料的授权范围内，按需读[写作规范](写作规范.md)，选择一个[模板](资料导航.md)及对应示范，格式按现有笔记习惯调整。读取已被进一步限定时不另找文件，依据已读说明整理。模板是可删减的骨架，不是填写任务。

先在对话给一段真正的内容预览，从本人能理解的具体场景进入，接一个关键例子或操作步骤，通常一屏以内；简短说明用途、准备放哪里、与哪篇已有记录关联。不要用计划、承诺或过程汇报代替成品。原文已好用时直接说明仅需保留或少量补充。

首次适配时，用户认可后在其指定位置保存示范副本，或按明确授权局部合并。若使用者已经明确材料、用途、位置并授权直接整理保存，就直接执行并交付结果，不为重复预览再等一次确认。没有具体可写位置时先给适合目标软件保存的内容；不猜“原文件夹”指哪个目录，不自行写入熟悉的职业仓、工程或原知识库。不创建整套空目录，不安装插件、不覆盖原规则。

保存后检查事实、目标阅读器中的链接、重复与范围。正文不要夹入“怎样与 AI 合作”“以后怎样使用本包”等说明；采用方式在对话说清一次即可。较长的来源、教学性质与补充范围统一放文末。理解例子必需的约定仍在正文交代；影响安全操作或事实判断的未知就近注明，不用后置说明掩盖。示例用标题或一句短话标明，不能写成使用者已完成的经历。

## 接到个人知识库

按现状选路线，必要时读[建立或接入个人知识库](建立或接入个人知识库.md)。不是要求所有人采用 Obsidian 架构：

| 现状 | 应交付什么 |
| --- | --- |
| 没有知识库 | 首篇属于本人的实用内容、本人选定的阅读位置、必要入口和下次追加方式；确认能打开与查用 |
| 有散笔记 | 一个主题的局部整理或入口，保留已有好内容；需要集中时小范围试用 |
| 有在用的知识库 | 根据具体缺口补内容、模板或关联，适配已有软件、格式和习惯；无收益就保留原系统 |

使用者尚未选软件时了解实际设备与阅读习惯后给一个简单方案和取舍，不先要求安装工具。页面式或其他笔记软件使用其原有标题、分区和链接，文件顶部的属性、目录与折叠提示都可删改。有文件工具只在确认位置写入；无法接入目标软件时提供适合粘贴的内容，不承诺自动导入。

已有材料的位置明确时优先补充。没有库时先完成首篇及必要入口，目录按真实内容逐步生长；首篇可放根目录。本人有重建或换软件意愿时，比较具体收益、迁移与维护成本，先做可回退的小范围试用，不一概劝迁移，也不一概禁止迁移。不把参考仓变成私人记录仓。

知识库建立后，在入口留下实际采用的少量整理约定，说明下次让 AI 读取哪里。让使用者当场从入口打开或搜索首篇，实际查看阅读效果；未操作就写未验证。先理解和使用自己那篇内容，再讲必要操作，不先讲整套架构。

保存前明确实际目标路径和相关已有文件；跨位置链接须确认阅读器能访问。笔记内的知识关系用有效链接，源码、完整日志与波形保留在原工程。未获授权查看关联内容时只说明待关联，不制造悬空链接。

若需要固定模板或接续约定，只保存使用者已经采用的部分，追加到其既有入口或既有规则，不建立并行规则。不要每次整理都让使用者确认同一约定；新对话是否读取该约定取决于实际工具和入口。

## 日常短指令

| 使用者说 | 处理方式 |
| --- | --- |
| 只收集 | 保存指定原始材料，不扩写 |
| 整理这份材料 | 先判断保留/优化/提炼，再给技术内容预览 |
| 补到某篇笔记 | 读该篇后局部合并，保留具体内容和来源 |
| 只解释，不记录 | 在对话回答，不写文件 |
| 帮我复习 | 按相关笔记给问题并反馈，不因此新建一篇 |
| 记录这个坑 | 写真实排查与可重复步骤，不附加训练任务 |
| 整理这阶段值得留下的内容 | 根据当前可见材料与个人规则，按需更新项目记录、已有知识或经验；不要求三类都生成 |
| 按这个岗位帮我挑复习内容 | 在授权范围选少量相关记录，给阅读顺序与理由，保留真实参与边界 |
| 继续这份项目记录 | 根据指定材料恢复实际状态，补结果或已决定的待办；已完成就收口 |

## 查用与复习后，把理解补回去

顶部恢复主线，后面保留例子、代码、原始输出和具体步骤，详细依据一般后置。学习笔记与适合讲述的经验可配一个回忆问题及紧邻的折叠口述参考；不要求先答题，用户不需要时移除，操作记录不强制变成训练。本人要求复习时按现有内容反馈，把本人确认的新理解补原篇，不另存整段答题记录，不自动提高掌握状态。

本地 Markdown 可沿用“类型、日期、领域、状态、证据、tags”；学习的状态表示掌握，经验/项目的状态表示进度，证据另记来源与验证范围。不另加并行的掌握字段；已有属性按实际需要适配，其他软件不强制 YAML。规则模板只是默认做法，不能替用户决定能力。

## 判断是否值得采用

看实际产物能否回答一个具体问题、是否保留关键细节、是否比原文更方便用，以及放置与关联是否合理。仅变短、生成更多文件、写得像专业报告都不是收益。需要反复回原文补核心操作的摘要不应作为唯一成品。可以保留原文；只有具体改善值得留下。

AI 可整理与定位材料，不能自动证明事实成立或本人掌握。未知就指出缺口，不编造实验、根因、测试或源码位置。主动训练和亲手练习仅在使用者有该目标时加入；[开发中的记录建议](开发协作参考.md)仅在有需要时提供。整理笔记不默认读取工程、改代码、运行测试、烧录、安装工具或改变开发方式；另有明确工程任务时按该任务授权与目标项目规则执行。工具提示不能技术性保证模型遵守，实际访问范围仍应限定。

## 复制给 AI

```text
读 README 和《资料/AI接入说明.md》，先了解我是否已有笔记、常用软件和实际需要；信息已给就不再问。
没有知识库时带我完成首篇、保存位置、入口与下次追加方式；已有系统就按我的习惯适配。
我提供材料后，先判断保留、局部优化或提炼；保留能直接使用的技术内容。
对照合适模板和成品，先给实际内容预览，并说明个人存放位置与必要关联。
不要默认生成接续摘要、附加复习训练或安排新学习任务。
我认可后按指定位置保存；没有位置先给适合保存的内容，不改原文或其他目录；已有直接保存授权不重复确认。
未知就说明，不编造实验、事实或掌握程度；使用说明放在对话里。
```
