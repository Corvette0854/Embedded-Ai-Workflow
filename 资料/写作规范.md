# 笔记写作规范

整理后的笔记应让本人愿意再次打开，并能回答一个具体问题。已有笔记好用就保留或局部补充；格式服务内容，不按每次提问机械新建文件。

## 先决定用途

学习笔记解释知识，经验案例帮助重现和排错，项目记录描述真实进度与链路。一个材料先选一个主要用途。参考[示范知识库](../示范知识库/总览.md)看实际成品，再按模板删减。

已有操作文档含完整参数、步骤、帧表和日志时，不要压成“去原文看”的泛泛摘要。可以只补顶部导航或提炼一个独立知识问题；详细事实仍只维护一个入口。独立试用副本用于比较，采用后不要求长期同时维护两份相同记录。

## 从具体场景进入

先写读者能想象的现象或问题，再用一个小例子解释主线。数字、动作、输入输出让人能跟着看；专业词首次简注中文，避免一开头堆缩写。必要代码配中文说明，无须代码也能讲清楚时就先讲例子。

教学示例在标题或一句短话中标明，较长的来源与适用范围放末尾；例子必需的约定仍在相关位置讲清楚。真实笔记保持真实，不能为故事完整补写根因或结果。

## 顶部方便看，正文方便用

| 用途 | 顶部先呈现 | 正文保留 |
| --- | --- | --- |
| 学习 | 一句话结论、关键主线、适用边界 | 具体例子、必要代码/数据、易错点与来源 |
| 经验 | 现象、最先检查什么、已确认结果 | 环境、真实排查、实际修复、再次操作顺序与验证 |
| 项目 | 当前目标、链路、实际进度 | 模块关系、版本与证据、已决定的待办；收口后不新增任务 |

开头尽量一屏，不能为了短而删掉关键操作。优先使用小表、必要代码块与清楚的小标题；函数首次出现简注中文职责。保留能定位问题的错误文本、输入输出、参数单位与条件，避免只写“检查配置”“查看日志”。

快速区只保留能唤回理解的主线，不把答案、细节和依据一次铺满。适合复习的学习与经验笔记配一个简短口述问题，答案紧接其后，使用默认折叠的 `> [!question]-` 提示块。读者可以直接短读，也可以展开自查；用户不需要时删去，不把它变成必做练习。详细解释、代码与排查证据留在后面，关键条件仍就近说明。

来源已有代码时选少量相关片段和位置；没有源码就不编造代码。解释性伪代码标明伪代码，教学输入标明假设。技术例子要说明谁输入、怎样变化、输出或观察什么。

## 用不同的折叠块，帮读者选择怎么看

按内容用途选择 Obsidian 原生提示块（Callout），不是为了彩色把所有段落装进框里：

| 类型 | 适合放什么 | 位置与写法 |
| --- | --- | --- |
| `question` | 一到三句口述答案，帮助回忆后核对 | 问题留在开头可见，答案紧接着用 `> [!question]- 口述答案` |
| `example` | 一个具体数值怎样变化、一小段代码或调用链 | 放在对应解释旁，用 `> [!example]- 展开具体例子`；正文先讲清主线 |
| `info` | 平台差异、外围补充、详细来源或额外解释 | 放在相关段落后或文末，用 `> [!info]- 补充说明`，标题具体到内容 |

类型带有不同默认颜色和图标，实际外观随主题而变；含义靠中文标题说明，不能只靠颜色传达。不安装插件，不复制个人主题配置。三个类型是常用选择，不要求每篇齐全；已经容易读的内容照常用段落、表格与小标题。

可直接采用的写法：

```markdown
> [!example]- 数字从12变成8时，文字区域怎样变化？
> 1. 原来的文字占两格。
> 2. 新文字只画第一格，第二格未处理时可能留下旧字符。
>
> 这里是机制说明，不代表已在某块板上验证。
```

`-` 紧接方括号表示默认折叠。块里的每一行，包括空行、序号、代码围栏与代码，都要保留 `>` 前缀；一个块结束后空一行，再写普通正文。源码摘录注明出处、变量/函数职责以及省略范围；没有源码不编造。把关键例子折叠后，关闭状态仍应读得懂主线。

供电、电平、损坏风险、结论成立的必要条件和影响当前操作的未知，必须在正文就近可见；需要醒目时用不带折叠符的 `> [!warning] 操作前先确认`，不能藏在折叠块里。实际结果、教学构造与候选方案在展开内容里仍明确区分。

## Obsidian 与普通 Markdown

本地 Markdown 采用相对链接、可搜索标题和少量有意义的属性；其他软件按本人习惯使用页面标题、分区和页面链接，属性可省略。Obsidian 中可用折叠 Callout 放补充或复习答案；不用 HTML `<details>` 代替普通笔记格式。其他阅读器可能展开 Callout，技术正文仍应独立可读。无需依赖插件。

模板中的提示文字、空栏目和填表说明在成品里移除；模板末尾的“看一篇成品”“中文入口”等本包导航也不复制到个人笔记。成品关联根据实际保存位置重新核对，不沿用模板目录中的相对路径。已有属性与目录不批量迁移。操作参考和项目记录不强制插入口述题；经验笔记的折叠回顾不意味着安排额外训练，也不要求读前先答题。

## 依据与状态简明但清楚

AI 帮你解释完一段代码，你读着觉得有道理；过几天想改它，却可能不知道从哪里下手。这时不必记成“已经掌握”，也不用把有用的解释丢掉，只要把内容依据和本人掌握分别留下：

| 想记什么 | 可以怎样写 |
| --- | --- |
| 这段解释有没有依据 | 按指定代码整理；哪些位置核对过，哪些还没有 |
| 我现在能做到什么 | 能跟着解释看懂；能否独立修改，仍待本人评估 |

比如解释提到“收到命令后取数据，再把数据发出去”，可以保留这条主线并链接实际核对的位置。设备没有运行，表现就留为未验证；没有独立改过，不因笔记完整就写成“能应用”。这是记录方法的示意，不是对读者能力的评估。以后回来，既能找到已弄懂的线索，也能分清还需确认的部分。

技术来源按需放在文末；影响结论或操作的缺口就近写清。成品不附整理过程汇报，不讲工具读了哪些文件，也不写参考包作者的经历。使用者自己的真实笔记仍要保留数据来源、测试条件与结果。

- 学习笔记的 `状态`：待本人评估 / 待读 / 初步理解 / 能复述 / 能应用，由本人表现决定。
- `证据`：待确认 / 官方资料已核对 / 源码已核对 / 日志已核对 / 待实测 / 已实测等，注明支持哪个结论。
- 经验/项目的 `状态`：进行中 / 待排查 / 已解决 / 已收口等进度，不等于能力等级。

本地默认属性包括：类型、日期、领域、状态、证据与 tags；用于整理与主题检索，日期未知不编造。已有系统不要求批量迁移，也不再加一个并行的掌握字段。不必每篇都用全部字段。实测说明版本、条件、结果与范围。来源无法访问或未实际读过，不称已核对；示例未运行不称已测试，假设不填成根因。未知就写当前无法判断及所缺依据，宁缺毋滥。

## 正文只保留这篇需要的内容

通用 AI 分工、长接续提示、授权流程、采用说明留在对话或既有入口，不默认追加到技术正文。下一步只写已有任务或用户已决定的动作；整理历史记录不能顺带布置新练习。

原始代码、日志和波形保留在有权使用的工程位置，笔记保留必要内容与有效入口。公司材料按原权限保存，真实个人资料不提交参考仓。

## 写完检查

使用者下次打开它，能直接理解或照着做吗？关键细节是否还在？有没有重复？实际位置和关联是否清楚？来源与未知是否准确？折叠关闭时主线是否完整，展开后有没有真正有用的例子、代码或依据？若原文更好用，就保留原文，不为统一格式简化成信息更少的摘要。

中文短标签的冒号放在加粗标记外，例如 `**学习后容易忘**：`，避免标点边界使部分 Markdown 阅读器显示原始星号；保存后检查实际渲染，不只看源文件。
