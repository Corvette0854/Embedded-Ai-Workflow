# 学习示例：数字变短了，为什么旧字符还留在屏幕上？

你把屏幕上的 `12` 改成 `8`，原来的第二个字符 `2` 还在那里。这很像在黑板上把“12”的“1”改成“8”，却忘了擦掉后面的“2”。

## 快速看懂

**写入新数字，不一定会擦掉旧数字占过的整片区域。**

```text
旧内容占两格 → 新内容只画一格 → 第二格可能仍留着旧字符
```

先分清两个问题：传给显示函数的数字是不是 8？显示函数有没有覆盖原来第二格？

### 想复习时，先说说看

刷新标志已经触发，为什么还可能留下旧字符？

> [!question]- 口述答案
> 刷新标志决定什么时候画；实际覆盖了多大的区域由绘制方式决定。只画新字符，不一定会处理旧尾部。

## 用几个格子想清楚

```text
原来： [1][2][ ][ ]
只写8：[8][2][ ][ ]
写整格：[8][ ][ ][ ]
```

第三行成立的前提是：绘制空格时，驱动确实用背景覆盖这一格。若空格不画背景，就要考虑清除字段区域后再重画。

把数字准备成“左侧放数字、右侧补空格”的文本，可以帮助支持背景覆盖的驱动重画原来整段区域。4 是本例的最小宽度，超过它不会自动截断；真实代码还要检查缓冲区、返回值和界面范围。

> [!example]- 代入数字8，看文字怎样补齐
> 下面只演示怎样准备文字，尚未调用显示驱动。
>
> ```c
> #include <stdio.h>
>
> int value = 8;              // 本例要显示的数字
> char text[8];               // 本例的文字缓冲区
> snprintf(text, sizeof(text), "%-4d", value); // 最小4字符宽度，左对齐
> // text 的可见内容是 "8   "，后面还有字符串结束符
> ```
>
> 输入是整数8，输出是补了三个空格的文字。`snprintf`（在指定大小的缓冲区中格式化文字）只准备文本；真正写到屏幕仍由显示驱动完成。这不是完整错误处理示范。

> [!info]- 为什么最小宽度不等于固定截断？
> `%-4d` 的4规定至少占四个字符：短值补空格，较长的值不会因此被缩成四个字符。字段允许多大数值、缓冲区是否足够、相邻位置能否被覆盖，要按自己的界面处理，不能把格式化宽度当成屏幕边界。

## 为什么这个判断能迁移？

这类现象也可能出现在固定位置的计数、温度或状态文字上。关键问题是**旧区域有没有被完整处理**，具体方法按驱动选择。

排查方法看[屏幕尾字符残留案例](../经验/屏幕数字变短后尾字符残留.md)；它在项目里的位置看[数据采集与显示](../项目/数据采集与显示.md)。

## 来源与适用范围

格子图说明覆盖范围，代码说明文本格式化；它们不是完整显示程序。

格式化规则核对于 [newlib C 库说明](https://sourceware.org/newlib/libc.html)，查阅于 2026-10-02。4 是最小宽度，超过4字符不会自动截断；真实代码仍需处理字段范围、缓冲区和返回值。是否支持空格覆盖背景，必须查看并验证目标显示驱动。
